# 编程猫家长异议话术卡

先读本文件的当前版本。本 Skill 是普通家长异议流程的最后一步：主对话先按 `codemao-sales-brain` 优先启动具名的 `Codemao Sales Brain` 子智能体；该类型不可用时按其规则启动 `default`，取得简短的出卡前判断，再依据当前弹药库 DOCX 核对候选套数正文是否贴合家长明确说出的对象与问题，最后在此逐字交付原文原图。子智能体的建议只用于定位，不能覆盖原件；有贴题原文且没有特殊套数依据时取第一套，追加时取同小节下一套。没有贴题原文时如实报缺卡，不强行按共同词出卡，也不自动写新话术。即使用户提供孩子、家长或决策背景，也不为补画像追问。若当前环境不能启动子智能体，由主对话按相同规则先判断，并如实说明未启用独立子智能体。只有用户明确要求“想新话术”“重新写一版”“不要照文档、原创一版”等创作任务时，才由 `codemao-sales-brain` 走原创分支。不得把“有个性化背景”自行解释成创作新话术。

用户提供 DOCX 并要求“设为我的弹药库”“替换我的 ORL”时，交给 `codemao-orl-import` 完成导入；不要要求用户手动设置标题样式或复制文件。

用户要的是卡片，直接交付，不叙述检索和制作过程。标题标明家长异议、来源文档中的节名和套数。逐字保留所选套数的原文、原有顺序、语音标记、占位符及原图；只增加必要的发送类型标签和原图展示，不润色、改写、删句、调序、补写或替换图片。原文没有语音或图片时如实标明，不为凑格式补造内容。一次只给一套。需核实的事实或风险提示放在卡片外，清楚标为核实提醒，不混入或改动原文。

## 弹药库与当前来源

“弹药库”的统一英文名是 **Objection Response Library**，缩写 **ORL**。本 Skill 中的弹药库是当前可用的异议处理 DOCX 文档集合；一份文档可以包含多个异议，每个异议小节下的一套可发送内容就是一组“弹药”。按家长异议定位小节，直接取对应套数的文字、语音提示和原图出卡。文档原件是出卡事实源，不改动原件；销售大脑使用的案例、政策和加工资料属于策略参考，不叫弹药库，也不覆盖原文。公开插件不附带个人弹药库，首次使用前须通过 `codemao-orl-import` 导入自己的 DOCX。

默认读取插件根目录与 `skills/` 并列的 `Objection Response Library/` 文件夹，文件名不限。每位成员可在自己本机的插件原件目录替换 ORL 文档，再刷新插件；各自的 ORL 互不影响。插件共用能力和个人 ORL 的更新方法见插件根目录的 `说明.md`。也可用 `CODEMAO_AMMO_DIR` 指向单个 DOCX 或存放 DOCX 的文件夹，或在调用时传 `--source`。脚本只扫描文件夹顶层 DOCX，不递归查子文件夹，忽略 Word 临时文件。同一异议出现在多份文档时，由当前成员保留或合并自己的现行版本；`--source` 可用于排查或临时指定，脚本不会猜哪个版本更新。项目资产和个人知识库只在原件不可用时作为备用资料，并先核对版本；不能冒充弹药库中的原文。PDF 仅用于辅助核对文字，不能拿旧图片拼作同版原图。

## 按需读取 DOCX

使用 Skill 自带的 `scripts/read-docx-card.py`，用 Python 3.10+ 执行。在 Codex 桌面端先通过 `load_workspace_dependencies` 获取自带 Python 路径，无需让组员另行安装；其他环境使用其可用的 Python。脚本每次读取现行 DOCX 的正文 XML 和图片关系，定位唯一匹配的异议及指定套数后，才解出这套用到的图片。不需要预建索引、抽取全部图片或维护全文缓存。

```text
python <Skill目录>/scripts/read-docx-card.py "没时间"
python <Skill目录>/scripts/read-docx-card.py "爸爸不同意" --set 2 --source <指定DOCX路径>
python <Skill目录>/scripts/read-docx-card.py --list
```

当文档放在插件的 `Objection Response Library/` 文件夹时，可以省略 `--source`。输出是 JSON，保留来源文件、原件小节名、套数、文字顺序和各张原图的绝对路径与 Markdown 引用。图片只是从原件按原字节写入本机 `~/.codex/cache/codemao-script-card/` 以便在对话里显示，不改变原件。原件更新后下一次读取会直接使用新版内容；不能把旧话术或图片当作新版。

新文档用 Word 的“标题 1～6”样式标记每个异议，套数用更深一级标题写“第一套”“第二套”或“方案一”等；下一条同级或更高标题视为本异议结束。未标注套数的小节整体按第一套读取。普通正文加粗不等于标题样式，脚本无法据此可靠划分小节。用 `--list` 可查看每份文档识别出的标题。

输入异议优先匹配文档标题；常用异议词仍兼容测试文档的旧标题。新文档标题宜直接使用家长常说的异议词；其他情况先用 `--list` 查看真实标题，再把标题作为查询参数。匹配多个标题或多份文档时不要猜，按报错指定完整标题或用 `--source` 指定文件。测试文档的常用对应关系：

| 家长异议 | 原件小节 |
|---|---|
| 没时间 | `⭐没有时间【时间图换成自己课线的】` 或 `⭐没时间以后再考虑` |
| 爸爸不同意／要商量 | `⭐跟爸爸商量` |
| 太贵了 | `⭐太贵了` |
| 孩子太小／以后学 | `⭐年龄小或以后学` |

原件中的 `[IMG 146] w0146.png` 一类标记对应原图位置；按脚本输出的顺序使用，不按行号猜图号，保留原后缀。视频附件只标注名称和所在位置，不冒充已取到视频。未标注多套的小节只取整节作为第一套；请求不存在的第二套时如实说明。

## 发前检查

- 出卡正文严格照录原文，包括旧称、宣传表述、医学/升学说法及占位符；不得静默改写或省略。若发现可能过时、无法核实或不宜对外的内容，在卡外另列核实提醒，并说明原文尚未核实。用户明确要求新创作或改写时，才按销售大脑规则生成新文案。
- 图片使用当前原件中对应位置的原图原字节，按原顺序嵌在相应步骤；不得裁切、转码、打码、重绘、替换或因为未核实而静默省略。若图片确实无法读取或显示，明确告知用户并停止把该卡标为完整。
- 不凭空补写孩子表现、课程安排、价格、优惠、退款政策或时限。`XX` 等原文占位符保持原样，并在卡外提醒发送前核实替换。

## Codex 交付

在 Codex 对话里使用标准 Markdown 图片语法和图片文件的绝对路径，让原图直接出现在对应原文步骤下。用户已实测可右键复制内嵌图片，因此无需“复制这张图”按钮，也无需 `show_widget`、剪贴板脚本或第二张配图卡。交付前确认路径存在并且图片实际显示；图不显示时先核对文件路径和后缀。卡片展示所选原文的完整内容，不输出未选套数或索引元数据。所有核实提醒置于卡片之外，不改卡内文字。
