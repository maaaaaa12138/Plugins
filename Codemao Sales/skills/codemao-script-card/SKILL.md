# 编程猫家长异议话术卡

## 固定回复主线

所有家长回复锁定遵循：**共情 → 简单解决家长当下的问题（先托住）→ 建立有利于销售的判断标准 → 赋能（图文并茂）→ 发送其他家长真实好评截图作证（大众心理）→ 收口逼单关单**。其中“简单解决”只为顺着家长当下的问题接住对话，降低对抗和退出感，不是把课程价值一次讲完；建立标准后，才按标准选择赋能并推进成交。话术卡是最后一个环节，但不能只交付孤立话术；赋能素材要和论点逐段衔接，真实好评是独立的社会证明环节，最后要给出明确下一步，珍惜家长每一次回复机会。
无论异议多短，都不能只交付“简单解决”一段；六步要在同一轮或紧凑连续的卡片里完整落地，后面的赋能、证据和收口不能等家长下一次回复才补。
遇到“今晚问问孩子”这类暂缓异议，开场要前置孩子的正向反馈（如“孩子前几天还跟我说他喜欢学”），先处理潜在的“孩子不喜欢”退路，再进入共情、判断标准、赋能、证据和收口；不能把孩子重新放到“要不要学”的否决位置。
真实好评作证时，默认必须组成 2～3 张互补证据组：孩子愿意学或坚持、学习表现或作品变化、老师/家长对服务的具体反馈。每张图紧跟一句解释，合起来证明同一个判断，不重复截图，不用无关好评凑数量；确实不足 2 张时，卡外明确说明缺少适配物料。
赋能一个重要价值点时，不要只放一张孤立图片；优先按“课程机制/规划图 → 老师服务或学情记录图 → 真实家长反馈图”组成 2～3 张证据链，分别说明怎么教、怎么跟、实际有什么变化。
可使用“3 赋能打法”：从教师服务、课程/教研、赛事与成长路径、品牌资质等方向中，选择三类不同赋能组合，逐段配图说明。真实家长反馈不算赋能，必须在三赋能之后单独发送，承担大众心理的证明作用。三赋能是不同价值方向的组合，不是同一卖点重复发三张图。
原创或基于 ORL 优化版中，三项赋能各自要对应本轮判断标准、孩子可观察的收益和一件贴题物料；不把同一套通用介绍贴给每位家长。ORL 逐字原文卡仍照原件交付，不按这条改写原文。

## 表达方式

原创或基于 ORL 优化时，对所有家长默认说人话、大白话：写老师平时会发的微信短句，直接说孩子做什么、老师怎么帮、家长能看到什么。把“泛思维课、逻辑拆解、能力迁移、课程体系、赋能”等内部或官方词换成具体动作；例如说“孩子自己把想法做成作品，做错了再找是哪一步出了问题”。可以用一个熟悉的生活场景解释难懂的价值，讲完马上回到孩子、课程和下一步。发前默读文字与语音，若像课程介绍或把书面稿念了一遍，就改成自然说法；两者不能重复。六步是内部组织顺序，不把“建立标准、赋能、社会证明、收口”当作给家长看的标题。ORL 逐字原文仍按原文交付，不据此改写。
- 所有异议都要用大白话和生活化案例：无论价格、时间、线上线下、竞品、孩子意愿、学校安排还是课程效果，都先用微信短句接住，再用一个家长熟悉的场景解释，马上回到孩子会怎么学、老师怎么带和下一步怎么安排。一轮最多用一个案例，不能写成说教或鸡汤；“孩子不喜欢”只是其中一个例子，可选一张刘星、周杰伦或郎朗劝学图，随后仍要接北大联合教研、北大教师培训和老师服务物料。
- 家长说“普及课后先看看”“长期课以后再报”时，不能把卡片收在“您再观察一下”。先承认家长想看真实表现，再给出三个可观察标准：孩子是否愿意继续做作品、遇到问题是否愿意再试、老师是否及时跟进；当前产品若有已核实的试学或后续安排，要在同一轮直接推进具体安排。
- 家长说时间要留给阅读、运动、学校学习或其他兴趣班时，先尊重这些安排，不把编程说成完全不占时间，也不强行制造“先占名额”。只有在核实当前课线任务量和安排后，才能用“先试学看是否适配”收口；赋能仍需落到孩子怎么学、老师怎么跟。
- ORL 是原文和物料弹药库，不是向量数据库。出卡前由销售大脑按语义判断可能对应的异议，再用脚本核对标题、正文、语音和原图；不能因为标题没有完全匹配词就漏掉贴题卡，也不能把语义推荐当作原文事实。

先读本文件的当前版本。本 Skill 负责有贴题原文时的出卡：主对话先按 `codemao-sales-brain` 优先启动具名的 `Codemao Sales Brain` 子智能体；该类型不可用时按其规则启动 `default`，取得简短的出卡前判断，再依据当前弹药库 DOCX 核对候选套数正文是否贴合家长明确说出的对象与问题，最后在此逐字交付原文原图。子智能体的建议只用于定位，不能覆盖原件；有贴题原文且没有特殊套数依据时取第一套，追加时取同小节下一套。没有贴题原文时如实报缺卡，由主对话让大脑切换原创模式并交付一版标明“原创”的可发送回复；不强行按共同词出卡。即使用户提供孩子、家长或决策背景，也不为补画像追问。若当前环境不能启动子智能体，由主对话按相同规则判断或原创，并如实说明未启用独立子智能体。用户明确要求“想新话术”“重新写一版”等创作任务时，也由 `codemao-sales-brain` 走原创分支。有贴题原文时，不得把个性化背景自行解释成创作新话术。

用户提供 DOCX 并要求“设为我的弹药库”“替换我的 ORL”时，交给 `codemao-orl-import` 完成导入；不要要求用户手动设置标题样式或复制文件。

用户要的是卡片，直接交付，不叙述检索和制作过程。标题标明家长异议、来源文档中的节名和套数。完整话术卡的硬性格式是**文字 + 语音 + 图片三件套**，三类物料缺一不可；排列组合由当前发送节奏决定，可以文字后接语音再配图，也可以按步骤交错展示。逐字保留所选套数的原文、原有顺序、语音标记、占位符及原图；只增加必要的发送类型标签和原图展示，不润色、改写、删句、调序、补写或替换图片。候选套数缺少文字、语音或图片时，不标为完整卡：继续检查同小节其他套、同异议的其他 ORL 文档，以及已有素材库中适配的家长好评、作品、课堂反馈或服务证明；仍无法凑齐时报告缺卡，不用虚构语音、随意配图或截图冒充原件。一次只给一套完整卡。需核实的事实或风险提示放在卡片外，清楚标为核实提醒，不混入或改动原文。

原创或组合素材出卡时，图片必须紧跟对应论点发送，不能在整段文字结束后无解释地集中堆图；**先看图再写话，图片必须直接证明前一句**。课程价值配课程/教研图，老师服务配服务/学情图，品牌实力配品牌/资质图；教材/北大合作图不能证明英语基础或老师辅导，其他学科图片也不能替代英语证据。没有直接适配图时标明“本轮无适配图”，不要硬凑图片。文字和语音要互补：理性内容用文字，感性内容用语音；两者不能先后重复同一个结论。如果语音已经完成共情，文字就直接进入理性判断、课程赋能或下一步安排，不再复述家长原话和情绪。
竞品比较时必须核对卖点归属；“一学九练”属于猿编程，不能写成编程猫的特点。只能使用当前已核实的编程猫课程和服务事实，不把历史竞品话术中的攻击性或旧口径直接发给家长。
“猿编程直播、编程猫录播”这类异议不能只回答“我们也有老师服务”。完整卡要说明录播为什么适合编程：课程规划让孩子按阶段反复练习，北大联合教研/课程研发/教师培训证明课程不是普通视频，老师服务和学习档案证明录播后仍持续跟进；三类图片分别紧跟对应论点，再进入真实反馈和试学收口。
使用“北大联合教研”时必须完成招牌外化：先说合作事实，再用大白话说明它怎样影响孩子的学习路径、作品和老师跟进。只发合作图、不解释孩子得到什么，不算完成赋能；不得把合作招牌说成学会、获奖或升学保证。
- 只要赋能段涉及课程价值、课程体系、教研、师资或老师服务，都必须外化北大联合教研、课程研发或教师培训，不限于“能不能便宜点”“太贵了”这类价格异议。先说明合作事实，再用大白话翻译成孩子能得到的分阶段路径、作品练习和老师跟进；按“北大课程价值 → 老师服务 → 真实家长反馈”逐段配图，最后用已核实的下一步安排收口。
- 北大赋能不能只放一张联合教研图：讲课程价值时配联合教研/课程设计物料；讲师资或老师服务时必须追加北大教师培训、研修或师资标准物料。优先按“联合教研课程图 → 北大教师培训图 → 老师服务/学情图”组合，每张图紧跟对应论点，避免赋能不充分。

默认逐字保留所选套数的原文、原有顺序、语音标记、占位符及原图；只增加必要的发送类型标签和原图展示，不润色、改写、删句、调序、补写或替换图片。若用户明确允许优化，或原文与当前家长语境明显不匹配，可以在原文逻辑、事实和物料基础上优化，标题明确标注“基于 ORL 优化版”，不得冒充逐字原文。

## 弹药库与当前来源

“弹药库”的统一英文名是 **Objection Response Library**，缩写 **ORL**。ORL 文件夹内的所有内容都属于当前成员的可用弹药，包括 DOCX 原文、快捷方式指向的图片素材，以及成员放入其中的其他销售物料；不能因为文件不是 DOCX 就把它排除在弹药库之外。DOCX 一份文档可以包含多个异议，每个异议小节下的一套可发送内容就是一组“弹药”。按家长异议定位小节，直接取对应套数的文字、语音提示和原图出卡；素材文件按异议和线上课程场景筛选使用。只有文字、语音、图片三类物料齐全，才可以交付为完整卡。文档原件是出卡事实源，不改动原件；销售大脑使用的案例、政策和加工资料属于策略参考，不叫弹药库，也不覆盖 ORL 中的内容。公开插件不附带个人弹药库，首次使用前须通过 `codemao-orl-import` 导入自己的 DOCX 或放入自己的物料。

默认读取插件根目录与 `skills/` 并列的 `Objection Response Library/` 文件夹，文件名不限。每位成员可在自己本机的插件原件目录替换 ORL 文档，再刷新插件；各自的 ORL 互不影响。插件共用能力和个人 ORL 的更新方法见插件根目录的 `README.md`。也可用 `CODEMAO_AMMO_DIR` 指向单个 DOCX 或存放 DOCX 的文件夹，或在调用时传 `--source`。脚本扫描文件夹顶层 DOCX，并扫描顶层 Windows `.lnk` 快捷方式指向的素材文件夹，递归识别其中的 PNG、JPG、JPEG、WEBP、GIF、BMP 图片；因此每位同事只要把自己电脑上的“图形化物料”文件夹快捷方式放进 ORL，脚本就能读取自己的图片路径，不需要把个人素材上传插件或 GitHub。`--materials` 可单独列出已识别素材，`--list` 也会附带素材清单和快捷方式警告。忽略 Word 临时文件。同一异议出现在多份文档时，由当前成员保留或合并自己的现行版本；`--source` 可用于排查或临时指定，脚本不会猜哪个版本更新。项目资产和个人知识库只在原件不可用时作为备用资料，并先核对版本；不能冒充弹药库中的原文。PDF 仅用于辅助核对文字，不能拿旧图片拼作同版原图。

## 按需读取 DOCX

使用 Skill 自带的 `scripts/read-docx-card.py`，用 Python 3.10+ 执行。在 Codex 桌面端先通过 `load_workspace_dependencies` 获取自带 Python 路径，无需让组员另行安装；其他环境使用其可用的 Python。脚本每次读取现行 DOCX 的正文 XML 和图片关系，定位唯一匹配的异议及指定套数后，才解出这套用到的图片。不需要预建索引、抽取全部图片或维护全文缓存。

```text
python <Skill目录>/scripts/read-docx-card.py "没时间"
python <Skill目录>/scripts/read-docx-card.py "爸爸不同意" --set 2 --source <指定DOCX路径>
python <Skill目录>/scripts/read-docx-card.py --list
python <Skill目录>/scripts/read-docx-card.py --materials
```

当文档放在插件的 `Objection Response Library/` 文件夹时，可以省略 `--source`。输出是 JSON，保留来源文件、原件小节名、套数、文字顺序和各张原图的绝对路径与 Markdown 引用。图片只是从原件按原字节写入本机 `~/.codex/cache/codemao-script-card/` 以便在对话里显示，不改变原件。原件更新后下一次读取会直接使用新版内容；不能把旧话术或图片当作新版。
快捷方式素材输出的是同事本机的绝对路径，直接使用原图，不复制到插件；快捷方式目标不存在、不是文件夹或无法解析时只在 `material_warnings` 中提示，不影响 DOCX 出卡。线上课程异议优先从这些素材中筛选线上授课、线上作品、老师服务、学习反馈和课程价值证明，不能拿无关线下课堂图凑数。弹药库原图与快捷方式目标素材均可展示，最终发送由销售手动决定。

新文档用 Word 的“标题 1～6”样式标记每个异议，套数用更深一级标题写“第一套”“第二套”或“方案一”等；下一条同级或更高标题视为本异议结束。未标注套数的小节整体按第一套读取。普通正文加粗不等于标题样式，脚本无法据此可靠划分小节。用 `--list` 可查看每份文档识别出的标题。

输入异议优先匹配文档标题；常用异议词仍兼容测试文档的旧标题。新文档标题宜直接使用家长常说的异议词；其他情况先用 `--list` 查看真实标题，再把标题作为查询参数。匹配多个标题或多份文档时不要猜，按报错指定完整标题或用 `--source` 指定文件。测试文档的常用对应关系：

| 家长异议 | 原件小节 |
|---|---|
| 没时间 | `⭐没有时间【时间图换成自己课线的】` 或 `⭐没时间以后再考虑` |
| 爸爸不同意／要商量 | `⭐跟爸爸商量` |
| 太贵了 | `⭐太贵了` |
| 孩子太小／以后学 | `⭐年龄小或以后学` |

原件中的 `[IMG 146] w0146.png` 一类标记对应原图位置；按脚本输出的顺序使用，不按行号猜图号，保留原后缀。ORL 中的视频、音频和其他文件也属于弹药；能读取到路径时按原文件标注和交付，不把它们冒充图片。未标注多套的小节只取整节作为第一套；请求不存在的第二套时如实说明。

## 发前检查

- 出卡正文严格照录原文，包括旧称、宣传表述、医学/升学说法及占位符；不得静默改写或省略。若发现可能过时、无法核实或不宜对外的内容，在卡外另列核实提醒，并说明原文尚未核实。文字、语音、图片三件套齐全后才交付完整卡。用户明确要求新创作或改写，或当前 ORL 缺少贴题卡时，才按销售大脑规则生成新文案；原创交付也沿用三件套格式，语音和图片必须分别标出来源或核实状态。
- 图片使用当前原件中对应位置的原图原字节，按原顺序嵌在相应步骤；不得裁切、转码、打码、重绘、替换或因为未核实而静默省略。若图片确实无法读取或显示，明确告知用户并停止把该卡标为完整。
- 不凭空补写孩子表现、课程安排、价格、优惠、退款政策或时限。`XX` 等原文占位符保持原样，并在卡外提醒发送前核实替换。

## Codex 交付

在 Codex 对话里使用标准 Markdown 图片语法和图片文件的绝对路径，让原图直接出现在对应原文步骤下。用户已实测可右键复制内嵌图片，因此无需“复制这张图”按钮，也无需 `show_widget`、剪贴板脚本或第二张配图卡。交付前确认路径存在并且图片实际显示；图不显示时先核对文件路径和后缀。卡片展示所选原文的完整内容，不输出未选套数或索引元数据。所有核实提醒置于卡片之外，不改卡内文字。
