# 导入个人弹药库

用户只需给出 DOCX 并说要用它作自己的弹药库。你完成检查、整理、安装和验证，不要求用户手动套 Word 标题样式、移动文件或运行命令。只在异议或套数边界无法可靠判断时，指出具体位置请用户确认；未确认时不要猜测并覆盖现行 ORL。

使用 `scripts/import-orl-docx.py`。Codex 桌面端通过 `load_workspace_dependencies` 取得 Python 路径；脚本需要该环境的 `lxml`，不要求销售自行安装。先用话术卡脚本的 `--list --source <DOCX>` 检查原件标题，并抽查一条异议及原图。若原件已能正确出卡，直接运行 `adopt <DOCX>` 原样接入，不重写文档。否则运行 `inspect <DOCX>` 查看带段落编号的候选文字；需要更多上下文时用 `--all`、`--offset`、`--limit` 分页。根据实际内容判断每个异议从哪段开始、标题是什么、各套从哪段开始。不要仅凭加粗或短句自动判定。生成 UTF-8 JSON 计划：

```json
{"objections": [{"paragraph": 12, "title": "太贵了", "sets": [13, 22]}]}
```

`paragraph` 是异议标题或首段正文的编号；`sets` 是各套标题或首段正文编号。只写有证据支持的边界；若文档未分套，省略 `sets`。保留原件，不重写销售话术。计划确认后运行 `apply <DOCX> --plan <计划JSON>`。脚本只调整标题结构或插入必要的标题，逐项复制原 DOCX 的其他内容与图片；先验证生成稿能被话术卡识别，再将当前个人 ORL 的 DOCX 移到插件外的备份目录并放入新稿。`adopt` 同样先检查标题并备份旧版，但保留合格原件的全部字节。原件在原位置保持不变；若原件本来就在 ORL，旧件会移入备份。脚本通过插件安装记录找到当前成员的插件原件目录，不写缓存目录。

安装成功后执行脚本输出的刷新命令，再用 `codemao-script-card/scripts/read-docx-card.py --list` 从**已安装插件副本**检查新标题，并抽查一条异议和原图。若刷新失败，说明原件已更新但当前安装副本尚未刷新，继续处理刷新；不要报告导入已完全生效。成功时只告诉用户已导入的文档、识别出的异议数量及有无待确认项。个人 ORL 的变化不增加插件版本号，也不影响其他成员。
